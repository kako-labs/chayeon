## 앱명 / 프로젝트명

차연

## 1. 앱 한 줄 소개

내 주행 습관과 차량 관리가 프로필이 되어 근처의 사람과 서로 원할 때만 목소리로 이어지고, 멀어지면 저절로 끊기는 차량용 인연 앱입니다.

## 2. 기획 배경

운전 스타일은 사람마다 천차만별입니다. 그리고 많은 사람이 그 차이로 상대를 고릅니다. "운전이 난폭한 사람은 싫다", "운전할 때 차분한 사람이 좋다"처럼 운전 습관이 이상형을 가르는 기준이 되기도 합니다. 차는 사람이 정말 많은 시간을 보내는 공간이라, 그 안에서의 모습에는 성격이 고스란히 드러납니다. 서두르는지 기다리는지, 다음 움직임을 미리 알려 주는지, 함께 탄 사람을 배려하는지가 보입니다. 운전 행동과 성격의 관계를 다룬 연구 34편을 종합한 분석에서도 위험하고 공격적인 운전은 성실성과 친화성이 낮을수록 많이 나타났습니다.[1] 중국 운전자 296명을 조사한 연구에서는 신중한 운전 스타일이 성실성, 친화성과 함께 높게 나타났습니다.[2]

그런데 이 정보는 어디에도 쓰이지 않습니다. 데이팅 앱의 자기소개는 누구나 원하는 대로 꾸밀 수 있어 믿기 어렵습니다. 반면 옆 사람이 놀라지 않게 미리 멈추는 습관이나 떠나기 전에 차를 살피는 습관은 말로 꾸미기 어렵습니다. 차연은 차량이 지켜본 이런 운전 정보를 프로필로 만듭니다. 상대는 그 프로필을 자유롭게 보고, 매칭 조건으로 쓰고, 통화하는 중에도 짧게 확인합니다.

만남이 일어나는 곳도 차 안입니다. 사람들은 매일 같은 도로와 휴게소, 충전소를 지나치지만, 그 순간에 스친 사람과 안전하게 말을 건넬 방법이 없습니다. 운전 중에는 글을 쓸 수 없으니 이어진 두 사람은 목소리로 이야기해야 합니다. 그래서 차연에서는 연결이 곧 통화이고, 주행 중에도 통화가 이어집니다.

모르는 사람과 이어지는 서비스에서 가장 먼저 걱정되는 것은 원치 않는 접근이 계속되는 일입니다. 2022년 미국 성인 6,034명을 조사한 결과, 데이팅 앱이나 사이트를 써 본 사람의 30%가 관심이 없다고 밝힌 뒤에도 연락을 계속 받았다고 답했습니다. 50세 미만 여성 이용자에서는 43%였습니다.[3] 한 번 이어진 상대가 계속 연락하거나 따라올 수 있다면 누구도 마음 편히 켜 두기 어렵습니다. 그래서 차연의 연결은 오래 남지 않게 만들었습니다. 두 차가 멀어지면 통화는 저절로 끝나고, 통화 중에도 어느 쪽이든 바로 끊을 수 있습니다. 끝난 뒤에는 상대의 위치도 연락처도 남지 않으며, 다시 이어지려면 두 사람이 모두 애프터를 수락해야 합니다.

차량 안에서 이런 연결을 만들려면 다섯 가지 불편을 먼저 풀어야 한다고 봅니다.

| 불편한 순간 | 왜 해결이 필요한가 |
|---|---|
| 내 위치가 드러날까 걱정된다 | 위치를 공유하면 집이나 자주 가는 곳이 추정될 수 있습니다 |
| 원하지 않는 접촉을 받을 수 있다 | 한쪽의 요청만으로 대화가 열리면 불쾌한 접근을 막기 어렵습니다 |
| 한 번 이어진 사람이 계속 따라올 수 있다 | 연결이 끝나지 않거나 상대가 나를 다시 찾을 수 있으면 스토킹으로 이어질 수 있습니다 |
| 운전에 방해될 수 있다 | 주행 중 탐색과 입력은 안전을 해칩니다 |
| 프로필을 믿기 어렵다 | 글과 사진만으로는 어떤 사람인지 알기 어렵습니다 |

차연은 이 다섯 가지를 제품의 규칙으로 풉니다. 위치는 근처 여부와 집 보호 구역을 판단할 때만 쓰고, 집 근처에서는 발견을 쉽니다. 양쪽이 수락하거나, 주차 중에 미리 정해 둔 자동 연결 조건을 서로 만족해야 연결됩니다. 연결은 두 차가 가까이 있는 동안만 이어지고, 멀어지거나 한쪽이 통화를 끊으면 바로 끝납니다. 새 사람을 찾고 입력하는 일은 주차 중에만 하고, 주행 중에는 목소리로만 이어집니다. 그리고 차량이 아는 주행과 관리 습관을 본인이 고른 만큼만 점수로 보여 줍니다.

이 문제의식은 팀의 가설이며, 실제 수요는 사용자 검증으로 확인해야 합니다.

## 3. 앱 주요 기능 및 차량 특화 요소

### 운전 프로필: 차가 만들어 주는 프로필

앱 화면에서는 이 프로필을 `드라이브 시그니처`라고 부릅니다. 오래 머무는 차 안의 운전 습관은 사람의 성향을 보여 줍니다. 차분하게 운전하는 사람을 만나고 싶다는 선택을 주행과 차량 관리의 공개 점수로 구체화합니다. 원시 신호는 차 안에서 요약하고, 상대는 60점 이상에서 본인이 공개한 점수만 봅니다. 이 점수는 후보 선택과 주행 중 자동 연결 조건에 쓰이고 통화 중에도 짧게 확인할 수 있습니다. 내 프로필에서는 점수마다 어떤 주행에서 나왔는지 근거를 볼 수 있습니다.

| 구성 | 내용 |
|---|---|
| 주행 스타일 특성 7가지 | 부드러운 주행, 여유로운 제동, 깜빡이 매너, 한결같은 항속, 벨트 먼저, 긴 여정파, 밤 드라이브파 |
| 차량 관리 특성 5가지 | 타이어 관리, 미리 채우는 습관, 배터리 아끼기, 소모품 점검, 실내 공기 챙김 |
| 칭호 | 공개한 특성으로 만드는 한 줄 소개입니다. 예: `깜빡이를 잊지 않는 드라이버`, `떠나기 전에 살피는 드라이버` |
| 시그니처 매듭 | 습관에 따라 모양이 달라지는 붉은 3D 매듭입니다. 궁합 화면에서는 두 사람의 매듭이 빨강과 진주색으로 엮입니다 |
| 드라이브 궁합 | 점수 없이 문장으로 보여 줍니다. 예: `둘 다 출발 전에 안전부터 챙겨요` |
| 주행 후 요약 | 주차하면 이번 주행이 어떻게 반영됐는지 나에게 먼저 보여 줍니다. 다른 사람이 운전했다면 뺄 수 있습니다 |
| 공개 범위 | 특성마다 공개를 고르고, 상대에게 보이는 모습을 미리 봅니다. 밤 드라이브는 기본 비공개입니다 |

지키는 원칙은 다음과 같습니다.

- 속도, 제동, 조향 같은 원시 값은 메모리에서만 처리하고 저장하거나 전송하지 않습니다. 파생 지표만 기기에 저장합니다.
- 상대와 서버에는 내가 공개한 특성의 단계와 60~100점만 갑니다. 취향 특성은 점수 없는 배지이며 개인 근거·낮은 점수·순위는 상대에게 보이지 않습니다.
- 빠르거나 공격적인 운전을 칭찬하는 특성, 점수, 순위를 만들지 않습니다.
- 내 실시간 점수나 코칭은 주행 중 보여 주지 않습니다. 상대의 공개 점수 최대 2개는 통화·수신 화면에서 정적으로 보여 주고 내 근거는 주차 후에 봅니다.
- 차량이 제공하지 않는 신호는 `이 차량에서 제공되지 않아요`로 표시하고 0으로 계산하지 않습니다.
- VIN, 차량 등록 정보, 차량 모델, 번호, 외형은 읽지 않습니다.
- `혼자 둘러보기`는 첫 선택에서 가상 상대임을 알리고, 내 시그니처 근거에 출처를 한 줄로 보여 줍니다. 서버에 연결한 모드에서는 가상 상대와 합성 데이터에 작은 표시를 유지합니다.

### 멀어지면 끝나는 연결

차연에서 연결은 곧 음성 통화이고, 그 통화는 두 차가 가까이 있는 동안만 이어집니다. 서로 멀어지면 `서로 멀어져서 통화가 끝났어요`라는 안내와 함께 통화와 연결이 같이 끝납니다. 통화 중에는 주차 중이든 주행 중이든 `통화 끊기`가 화면에서 가장 크게 보이고, 누르는 즉시 연결이 끝납니다.

끝난 연결은 닉네임, 시각, 이어진 시간, 끝난 이유만 기록에 남습니다. 상대의 위치와 지나온 경로, 연락처는 어디에도 남지 않아 끝난 뒤에 상대를 다시 찾아갈 방법이 없습니다. 주행 중 자동 연결은 통화가 끝난 뒤 10분 동안 쉬고, 그날 한 번 끝난 상대와는 자동으로 다시 이어지지 않습니다. 차단하면 노출과 요청, 통화가 모두 끊깁니다.

다시 이어지는 길은 애프터 하나입니다. 기록에서 한쪽이 신청하고 상대도 수락해야 서로 고른 카카오톡·인스타그램 아이디가 교환됩니다.

| 기능 | 해결하는 문제 | 차량 특화 요소 |
|---|---|---|
| 발견 켜기/끄기 | 원할 때만 참여합니다. 끄면 새 노출과 요청이 멈춥니다 | 주차 중에만 조작합니다 |
| 집 보호 구역 | 집 근처에서는 발견을 쉬어 집이 추정되는 일을 줄입니다. 이어져 있던 상대에게는 멀어져서 끝난 것과 똑같이 보입니다 | 집 좌표와 반경은 차 안에만 저장하고 서버로 보내지 않습니다 |
| 오늘의 인연 카드 | 칭호, 공개 점수 상위 3개, 잘 맞는 점 수를 관심사보다 먼저 보여 줍니다 | 지도, 거리, 방향, 차량 식별 정보를 표시하지 않습니다 |

| 조건에 맞으면 자동 연결 | 공개 점수의 최소값과 공통 관심사로 원하는 사람을 고릅니다 | 자동 연결을 고르고 발견을 켠 채 주행할 때만 자동으로 요청하고 수락합니다. 집 보호, 차단, 통화 뒤 10분 대기, 당일 재시도 금지를 적용합니다 |
| 일시 연결 음성 통화 | 수락하면 바로 통화를 시작합니다. 주차 중에는 공개 공통 관심사·궁합·칭호를 이야깃거리로 보여 줍니다 | 주행 중 통화를 유지하고 음소거와 통화 끊기만 크게 제공합니다 |
| 멀어지면 자동 종료 | 원치 않는 연결이 이어지지 않도록, 서로 멀어지면 통화와 연결이 저절로 끝납니다 | 차량의 이동이 연결의 시작과 끝을 정합니다 |
| 스친 인연 기록 | 닉네임, 시각, 기간, 끝난 이유만 남깁니다 | 지나온 위치와 경로를 저장하지 않습니다 |
| 애프터 | 양쪽이 다시 원할 때만 고른 연락처 ID를 교환합니다 | 이후에는 거리와 상관없이 이어집니다 |
| 차단·신고·정리 | 차단하면 노출, 요청, 통화와 앱의 교환 연락처 접근이 즉시 끊깁니다 | 로그아웃하면 공유 차량에 개인 정보를 남기지 않습니다 |

### 차량에서만 가능한 경험

- **운전 습관이 자기소개가 됩니다.** 사진과 글로 꾸민 프로필이 아니라, 평소의 주행과 차량 관리로 나를 보여 줍니다. 차 밖에서는 만들 수 없는 프로필입니다.
- **주차하는 순간이 경험의 절정입니다.** 주행이 쌓여 시그니처가 생기면, 주차 후 매듭이 그려지며 내 칭호와 특성을 처음 보여 줍니다.
- **이동이 곧 관계의 규칙입니다.** 휴대폰 앱처럼 언제든 찾아보는 서비스가 아니라, 같은 길 위에 있는 동안만 이어지는 만남입니다.
- **주행 상태에 맞춰 앱이 달라집니다.** 연결을 수락하면 통화가 시작되고 주행 중에도 목소리로 이어집니다. 주행 중에는 탐색과 입력을 잠그고 음소거와 통화 끊기만 크게 남깁니다. 기어가 D이면 멈춰 있어도 주행 중으로 보고, P로 바꾸면 화면이 다시 펼쳐집니다. `주행 중 연결`은 끄기, 전화처럼 받기, 조건에 맞으면 자동 연결 가운데 하나를 주차 중에 고르며 기본은 끄기입니다. 수신과 통화 화면에는 상대의 칭호와 공개 점수 최대 두 개만 보여 줍니다.
- **붉은 실로 상태를 보여 줍니다.** 뻗은 실은 요청, 이어진 실은 연결, 끊어진 실은 종료, 구슬 줄은 애프터 대기, 매듭은 이어진 인연입니다.

### 안전과 개인정보 원칙

위치 기반 데이팅 앱 15개를 분석한 2024년 연구에서는 6개 앱에서 상대의 정확한 위치를 특정할 수 있었습니다.[4] 차연은 거리와 방향을 화면에도 서버 응답에도 내보내지 않습니다.

- 상대에게 정확한 좌표, 거리, 방향, 궤적, 차량번호, 차량 외형, 집과 목적지를 제공하지 않습니다.
- 발견을 켜는 것과 개별 연결에 동의하는 것을 분리합니다.
- 주행 중이거나 차량 상태를 알 수 없을 때는 탐색, 직접 거는 요청, 입력, 설정 편집을 막습니다. 주행 중에는 미리 고른 방식에 따라 전화처럼 받는 수신 화면과 조건에 맞는 자동 연결만 열리고, 차량 상태를 알 수 없을 때는 통화 끊기만 남습니다.
- 집을 정하면 그 반경 안에서는 발견을 쉽니다. 위치를 확인할 수 없을 때도 쉬는 쪽으로 동작하고, 위치 사용 동의를 끄면 위치 읽기를 멈춥니다.
- 내 위치나 통신이 끊기면 내 화면에 그 사실을 안내합니다. 상대에게는 집 도착, 앱 종료, 통신 단절이 멀어진 경우와 똑같이 보입니다.
- 성인 이용자를 대상으로 합니다. 시연 단계의 자기 확인을 실제 연령 인증으로 표시하지 않습니다.

## 4. 주요 사용 시나리오

**상황:** 서로 모르는 성인 A와 B가 저녁에 같은 휴게 공간에 주차해 있습니다. 두 사람 모두 차연의 발견을 켜 둔 상태입니다. 시연 영상도 같은 순서로 A의 하루를 따라갑니다.

1. **운전 프로필:** A의 주행과 차량 관리 습관이 점수로 쌓입니다. 유효한 주행이 3번 모이면 주차 후 매듭과 칭호가 처음 나타납니다.
2. **공개 범위:** A는 60점이 넘는 특성 가운데 상대에게 보일 것을 고릅니다. 내 프로필에서는 `깜빡이 매너` 같은 점수가 어떤 주행에서 나왔는지 근거를 봅니다.
3. **발견:** 홈의 오늘의 인연에서 근처에 주차한 B의 카드를 봅니다. 칭호와 공개 점수가 먼저 보이고, 카드를 열면 함께하면 잘 맞는 점이 문장으로 나옵니다.
4. **요청과 수락:** A가 통화를 요청합니다. B가 수락하기 전에는 아무것도 열리지 않고, 수락하면 두 사람이 바로 음성 통화로 이어집니다.
5. **달리며 통화:** A가 기어를 D로 바꿔 출발해도 통화는 이어집니다. 화면에는 음소거와 통화 끊기만 크게 남습니다. 신호에 멈춰 있어도 D이면 주행 중이고, P로 바꾸면 이야깃거리가 다시 펼쳐집니다.
6. **멀어짐:** 두 차가 서로 멀어지면 통화가 저절로 끝나고 `서로 멀어져서 통화가 끝났어요`라는 안내가 나옵니다. 그 전에 어느 쪽이든 통화 끊기를 누르면 그 자리에서 끝납니다.
7. **애프터:** A가 기록에서 애프터를 신청하고 공유할 인스타그램 아이디를 고릅니다. B도 수락하면 그때 서로의 아이디가 보입니다. 인스타그램 QR은 주차 중에만 확인합니다.
8. **주행 중 자동 연결:** A는 주차 중에 `주행 중 연결`을 `조건에 맞으면 자동 연결`로 바꾸고 `여유로운 제동 90점 이상`을 조건으로 정합니다. 통화가 끝나고 10분이 지난 뒤 달리는 중에 조건에 맞는 C와 자동으로 이어지고, 앱은 `C님과 연결됐어요`라고 이름을 한 번 알려 줍니다.
9. **주행 후:** 주차하면 이번 주행이 프로필에 어떻게 반영됐는지 요약을 봅니다. 실제 차량 신호로 달린 주행도 같은 프로필에 쌓입니다.
10. **집 근처:** 집 보호를 켜 두면 집 근처에서는 발견을 쉬고, 홈에 `쉬는 중`으로 표시됩니다.

**경계 상황**

| 상황 | 앱의 동작 |
|---|---|
| B가 거절하거나 응답하지 않음 | 연결은 만들어지지 않고 기록에도 남지 않습니다. 거절 이유는 전달하지 않습니다 |
| 수락 시점에 상대가 이미 멀어짐 | 연결할 수 없다고 안내합니다. 다른 사람과 자동으로 연결하지 않습니다 |
| 연결 중에 집 근처에 도착함 | 바로 발견을 쉽니다. 상대에게는 잠시 확인 상태를 거쳐 멀어져서 끝난 것으로 보이고, 집 때문이라는 사실은 전달되지 않습니다 |
| 통화 중에 대화를 그만하고 싶음 | 주차 중이든 주행 중이든 통화 끊기를 누르면 통화와 연결이 함께 끝납니다 |
| 집 근처에서 요청을 받음 | 수락은 막고 쉬는 동안에는 수락할 수 없다고 안내합니다. 거절은 할 수 있습니다 |
| 불쾌한 상대를 만남 | 차단하면 노출, 요청, 통화와 앱의 교환 연락처 접근이 즉시 끊깁니다 |
| 함께 쓰는 차량에서 내림 | 로그아웃하면 이 차량의 프로필, 연락처, 주행 지표가 지워집니다 |
| 다른 사람이 내 계정으로 운전함 | 주행 후 요약에서 `내가 운전하지 않았어요`로 그 주행을 뺍니다 |
| 차량이 일부 신호를 제공하지 않음 | 그 특성은 제공되지 않는다고만 표시합니다. 나쁘게 평가하지 않습니다 |

## 5. 개발 계획

### 구현 범위

| 단계 | 범위 | 시연 표기 |
|---|---|---|
| 1차 제출 (구현 완료) | 운전 프로필, 전체 만남 흐름, 음성 통화, 주행 중 자동 연결과 집 보호 구역이 동작합니다. 서버 없이 `혼자 둘러보기`로 가상 상대를 만나고, 팀이 심사 기간에 운영하는 공개 서버에 연결하면 두 계정이 실제로 통화합니다 | `혼자 둘러보기`는 첫 화면의 모드 선택과 내 시그니처 근거에서 가상 상대와 데이터 출처를 알립니다. 서버 모드는 가상 상대와 합성 데이터에 작은 표시를 유지합니다 |
| 2차 PT | 화면 분할 등 차량 환경 대응을 넓히고 실차 조건을 확인합니다 | 실제 통신, 합성 위치 |

### 구조

- **앱:** Kotlin, Jetpack Compose, ViewModel, Repository 구조의 Pleos Connect용 Android 앱입니다. 모듈 의존 규칙은 빌드에서 검사합니다.
- **관계 엔진:** 상호 동의, 근접, 만료, 차단 규칙을 한 모듈에 모았습니다. 서버와 `혼자 둘러보기`가 같은 엔진을 실행해 두 모드의 규칙이 갈라지지 않습니다.
- **서버:** Ktor 단일 서버입니다. 사용자는 인증 토큰으로 식별하고, 클라이언트가 보낸 동의 값을 믿지 않습니다. 상태는 긴 폴링으로 동기화합니다.
- **시그니처 계산:** 순수 Kotlin 모듈로 분리해 같은 입력에 항상 같은 칭호, 궁합, 매듭을 만듭니다.
- **상태 규칙:** 사용자당 활성 일시 연결은 하나입니다. 취소, 만료, 종료는 최종 상태이며 늦게 도착한 수락이나 재접속으로 되살아나지 않습니다.

### 검증 항목

자동 테스트와 에뮬레이터 종단 시나리오로 다음을 확인합니다.

- 일방 요청만으로 음성 통화나 연락처 교환이 열리지 않습니다.
- 취소, 거절, 만료, 차단 뒤에 도착한 수락은 연결을 만들지 않습니다. 동시 수락과 재전송도 시험합니다.
- 제3의 계정은 다른 사람의 연결, 연락처, 기록을 읽거나 바꿀 수 없습니다.
- 차단당한 사람이 응답이나 동기화로 차단 사실을 알아낼 수 없습니다.
- 서버 응답과 저장 데이터에 위치, 궤적, 원시 신호, 개인 지표가 없습니다.
- 주행 중이거나 차량 상태를 알 수 없을 때 탐색, 직접 거는 요청, 입력, 설정 편집이 막힙니다. 주행 중 수신 화면은 전화처럼 받기나 자동 연결을 고른 경우에만 열리고, 자동 요청과 수락은 사전 동의와 조건을 검사합니다. 집 보호, 차단, 통화 뒤 대기 중에는 자동 동작이 없습니다.
- 공유 차량 로그아웃 뒤 다음 이용자에게 개인 화면과 연락처가 남지 않습니다. 집 기록도 지워집니다.
- 집 좌표와 반경이 요청과 응답 형식에 들어가지 않습니다.
- 상대가 받는 전체 동기화 내용과 종료 시각이 서버 만료와 명시적 이탈에서 같습니다.
- 앱이 강제 종료되면 앱의 추가 요청 없이 서버 만료로 연결이 끝납니다.
- 집 보호 중에는 후보가 보이지 않고 요청과 수락이 막히며, 재시도 중에 집 보호가 시작되면 다음 전송을 보내지 않습니다.

### 알려진 한계

- 시그니처는 차량 안 클라이언트에서 계산하므로 변조를 완전히 막지 못합니다. 공개 서비스로 가려면 서명된 차량 신호나 서버 검증이 필요합니다.
- 상대와의 근접 판단은 합성 값입니다. 실제 위치 기반 근접은 구현 경로만 있고 시연하지 않습니다. 기기 위치는 집 보호 구역에만 씁니다.
- 앱이 강제 종료되거나 차 전원이 꺼지면 서버 만료까지 최대 60초 동안 더 발견될 수 있습니다.
- 서버 운영자는 이탈 명령이 도착한 사실을 볼 수 있고, 이번 빌드에는 실제 위치 기반 이탈이 없으므로 집 보호 때문이라고 추측할 수 있습니다. 좌표와 반경은 서버에 가지 않습니다.
- 집을 정한 사용자가 터널이나 지하 주차장에서 위치를 잃으면 발견을 쉬고, 연결 중이었다면 끝날 수 있습니다. 며칠에 걸친 부재 패턴으로 집을 짐작하는 추론은 막지 못합니다.
- 임계값은 제품 기준이며 안전이나 의학 기준이 아닙니다. 실차 센서 노이즈에 맞춘 보정은 하지 않았습니다.
- 심사용 공개 서버는 팀이 운영하는 한 대입니다. 서버에 닿지 않으면 두 계정 연결은 되지 않고 `혼자 둘러보기`로 전체 흐름을 볼 수 있습니다.

## 6. 기대효과 및 발전 가능성

### 사용자 가치

- 꾸미기 어려운 평소 습관으로 나를 보여 주고, 같은 방식으로 상대를 알아볼 수 있습니다.
- 위치와 차량 식별 정보를 드러내지 않고 이동 중 새로운 사람과 연결될 수 있습니다.
- 원치 않는 접촉을 동의 절차와 차단으로 막습니다.
- 스쳐 지나간 만남을 서로 원할 때만 이어 갑니다.

### 타깃 고객

| 구분 | 내용 |
|---|---|
| 핵심 타깃 | 새로운 만남에 관심이 있고 서비스를 직접 켠 성인 차량 이용자 |
| 초기 유입 후보 | 제한된 행사와 커뮤니티, 충전·휴식 공간처럼 참여 의사가 있는 사람들이 모이는 곳 |
| 상용화의 핵심 조건 | 근처에 참여자가 충분히 있어야 합니다. 초기에는 특정 장소와 시간대에 집중합니다 |

특정 시설과의 제휴는 아직 없습니다.

### 예상 MAU와 Retention

아래 값은 측정 결과가 아닌 목표와 가정입니다. Pleos 탑재 차량 10만 대를 기준으로 잡았습니다.

| 지표 | 산식 또는 정의 | 값 |
|---|---|---|
| 예상 MAU | Pleos 탑재 차량 수 × 앱 설치율 × 월간 사용률 | 2,500명 |
| Pleos 탑재 차량 수 | 계산 기준으로 둔 가정 | 10만 대 |
| 앱 설치율, 월간 사용률 | 성인 이용자가 직접 켜는 서비스라는 점을 고려한 목표. 설치자 중 월 1회 이상 발견을 켠 비율을 월간 사용률로 봅니다 | 5%, 50% |
| Retention Rate | 발견을 켠 사용자 중 30일 뒤 다시 발견을 켠 비율 | 목표 25% |

차연은 근처에 참여자가 있어야 쓸 수 있어, 전국 평균보다 특정 장소와 시간대의 밀도가 먼저 필요합니다. 출시 초기에는 한 번 통화한 사용자가 다시 발견을 켜는 비율을 보고 목표를 조정합니다.

시연에서 확인하는 것은 흐름의 정확성입니다. 양측 동의 없는 연결, 중복 세션, 상호 수락 전이나 종료·차단 후 연락처가 노출되지 않는지 테스트로 검사합니다. 사용자 수요와 재방문은 측정하지 않았습니다.

### 수익 모델 후보

선택형 프로필 꾸미기, 관심사 큐레이션, 충전·휴식 공간과의 제휴 경험을 후보로 둡니다. 결제와 광고는 1차 개발 범위에서 제외합니다.

### 서비스 확대 계획

1. 실제 위치와 백그라운드 조건을 지원하고, 실차 신호로 시그니처 기준을 보정합니다.
2. 현재 PCM 통화를 Opus로 압축하고 실차 음질·오디오 라우팅을 검증합니다.
3. 현재 제공하는 카카오톡·인스타그램 ID 교환과 인스타그램 QR 경험을 사용자 검증으로 개선합니다.
4. 실사용자 가입, 연령 확인, 신고 처리 체계를 갖춰 공개 운영으로 넓힙니다.

### 상용화 전 과제

사용자 밀도 확보, 사칭과 원치 않는 접근 대응, 연령 확인과 신고 처리, 공유 차량의 계정 전환을 해결해야 합니다.

### 이번 제출의 통화 범위

연결 수락은 바로 통화 시작이며, 요청 화면에서 미리 알립니다. 주행 중에는 기존 통화를 이어가고 음소거와 통화 끊기를 제공합니다. 기본이 끄기인 주행 중 연결을 `전화처럼 받기`로 바꾸면 최소 정보로 받고, `조건에 맞으면 자동 연결`이면 미리 고른 공개 점수·관심사 조건에 맞을 때 자동으로 요청하고 수락합니다. 통화 종료 뒤 10분과 종료된 상대의 당일 재시도를 막습니다. 집 보호는 수락과 음성 송수신을 차단합니다. 통화 종료는 일시 연결 종료와 같으며 애프터 음성은 이번 범위에 없습니다.

PCM16 mono 16 kHz는 방향당 약 256 kbps(프로토콜 overhead 제외), 양방향 합계 약 512 kbps입니다. 서버는 짧은 메모리 대기열만 쓰고 녹음·보관·내용 로그를 만들지 않습니다. `혼자 둘러보기`와 서버 모드의 모든 가상 상대는 마이크와 음성 WebSocket 없이 미리 만들어 앱에 넣은 음성 클립으로 준비된 세 문장을 재생하고, 클립을 재생하지 못하면 Pleos 기기 내 음성이 대신 말합니다. 문장 시작부터 약 20초 간격을 둡니다. 포커스가 있을 때만 재생하고 종료·집 보호에서는 즉시 멈춥니다. SDK의 시작 콜백이 실제 소리 시작을 보장하지 않아 발화 중 표시는 제공하지 않습니다. 팀의 이전 앱 측정에서 초기 약 4.5초·이후 약 3초 지연이 있었으며, 차연의 기기 측정값은 아닙니다.

설치별 빈 프로필과 심사용 서버의 HTTPS 운영·저장·백업·APK URL 설정은 [배포 안내](../deploy/README.md)를 참고하세요. 계정과 공간을 고르는 UI는 없으며 닉네임을 직접 입력합니다.

## 심사용 서버 배포와 운영 제한

팀 운영 심사용 서버는 Caddy의 자동 HTTPS 인증서 발급과 인증 WebSocket 전달 뒤에 Ktor 서버를 둡니다. 기본 공간은 `default`이며 설치별 비밀 값으로 독립 계정을 식별합니다. 계정·공간 선택 UI는 제공하지 않습니다.

| 항목 | 기본값 |
|---|---|
| 사용자 정원 / 최대 공간 | 공간당 활성 사용자 50명 / 허용 공간 최대 64개, 시연 상대는 사용자 정원 제외 |
| 유휴 기준 | 30분. 로그아웃·유휴 계정은 좌석을 반환하고 데이터는 유지. 복귀 시 빈자리 필요, 파일 저장은 재시작 뒤에도 활동 시각 유지 |
| 허용 공간 | `CHAYEON_ALLOWED_ROOMS=default`. 쉼표 목록 지정, 로컬 검증은 `*` |
| HTTP 입장 | IP당 분당 30회 |
| HTTP 명령·sync 합산 | IP당 분당 600회, 인증된 계정당 분당 300회 |
| WebSocket 접속 시도 | IP당 분당 60회, 인증된 계정당 분당 20회 |
| 제한 테이블 | IP·계정 각각 최대 4,096개, 가득 차면 오래 사용하지 않은 항목 교체. 미등록 토큰은 IP 예산만 사용 |

기본 저장은 메모리이며 `CHAYEON_DATA_DIR`을 지정하면 권한 0600의 JSON 파일을 원자적으로 교체합니다. 프로필·동의·관계와 필요한 연락처를 저장하므로 운영자 접근과 백업을 제한해야 합니다. 관계 종료·차단·계정 삭제 시 해당 교환 ID를 제거하며 원시 차량 신호·좌표·음성은 저장하지 않습니다. 재시작은 활성 통화를 종료하고 유효한 대기 요청은 원래 만료 시각까지 유지합니다. 2026-11-13부터 팀 서버에서 이 이미지를 Docker로 실행하고 Cloudflare 터널로 공개 주소를 열어 운영하고 있으며, 공개 주소에서 두 계정 음성 왕복과 제3자 거절을 점검했습니다. Caddy로 직접 HTTPS를 여는 구성은 같은 이미지를 쓰는 다른 방법입니다. 구체적인 환경 설정·백업·초기화·APK URL 빌드는 [배포 안내](../deploy/README.md)를 따릅니다.
