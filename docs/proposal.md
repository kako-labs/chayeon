## 앱명 / 프로젝트명

차연 (가칭)

## 1. 앱 한 줄 소개

내 주행 습관과 차량 관리가 프로필이 되어, 같은 길 위의 사람과 서로 원할 때만 이어지는 차량용 인연 앱.

## 2. 기획 배경

사람들은 매일 차 안에서 시간을 보내고, 같은 도로와 휴게소, 충전소를 지나칩니다. 그러나 그 순간에 스친 사람과 안전하게 말을 건넬 방법은 없습니다. 차량 번호나 차량 외형, 정확한 위치를 드러내지 않고 연결할 수단이 없기 때문입니다.

데이팅 앱의 자기소개도 믿기 어렵습니다. 누구나 원하는 대로 꾸밀 수 있어서입니다. 반면 옆 사람이 놀라지 않게 미리 멈추는 습관이나, 떠나기 전에 차를 살피는 습관은 말로 꾸미기 어렵습니다. 함께 차를 탈 사람을 고를 때 궁금한 바로 그 모습이기도 합니다.

차량 안에서 이런 연결을 만들려면 네 가지 불편을 먼저 풀어야 한다고 봅니다.

| 불편한 순간 | 왜 해결이 필요한가 |
|---|---|
| 내 위치가 드러날까 걱정된다 | 위치를 공유하면 집이나 자주 가는 곳이 추정될 수 있습니다 |
| 원하지 않는 접촉을 받을 수 있다 | 한쪽의 요청만으로 대화가 열리면 불쾌한 접근을 막기 어렵습니다 |
| 운전에 방해될 수 있다 | 주행 중 탐색과 메시지 입력은 안전을 해칩니다 |
| 프로필을 믿기 어렵다 | 글과 사진만으로는 어떤 사람인지 알기 어렵습니다 |

차연은 이 네 가지를 제품의 규칙으로 풉니다. 위치는 근처 여부와 집 보호 구역을 판단할 때만 쓰고, 집 근처에서는 발견을 쉬며, 양쪽이 수락해야 연결되고, 조작은 주차 중에만 할 수 있습니다. 그리고 차량이 아는 주행과 관리 습관을 본인이 고른 만큼만 프로필로 보여 줍니다.

이 문제의식은 팀의 가설이며, 실제 수요는 사용자 검증으로 확인해야 합니다.

## 3. 앱 주요 기능 및 차량 특화 요소

### 드라이브 시그니처: 차가 만들어 주는 프로필

차연의 중심 기능입니다. 주행과 차량 관리 신호를 차 안에서 요약해, 상대에게 매력으로 읽히는 프로필로 바꿉니다.

| 구성 | 내용 |
|---|---|
| 주행 스타일 특성 7가지 | 부드러운 주행, 여유로운 제동, 깜빡이 매너, 한결같은 항속, 벨트 먼저, 긴 여정파, 밤 드라이브파 |
| 차량 관리 특성 5가지 | 타이어 관리, 미리 채우는 습관, 배터리 아끼기, 소모품 점검, 실내 공기 챙김 |
| 칭호 | 공개한 특성으로 만드는 한 줄 소개입니다. 예: `깜빡이를 잊지 않는 드라이버`, `떠나기 전에 살피는 드라이버` |
| 시그니처 매듭 | 습관에 따라 모양이 달라지는 붉은 3D 매듭입니다. 궁합 화면에서는 두 사람의 매듭이 빨강과 진주색으로 엮입니다 |
| 드라이브 궁합 | 점수 없이 문장으로 보여 줍니다. 예: `둘 다 출발 전에 안전부터 챙겨요` |
| 주행 후 요약 | 주차하면 이번 주행이 어떻게 반영됐는지 나에게 먼저 보여 줍니다. 다른 사람이 운전했다면 뺄 수 있습니다 |
| 공개 범위 | 특성마다 공개를 고르고, 상대에게 보이는 모습을 미리 봅니다. 밤 드라이브는 기본 비공개입니다 |

지키는 원칙은 다음과 같습니다.

- 속도, 제동, 조향 같은 원시 값은 메모리에서만 처리하고 저장하거나 전송하지 않습니다. 파생 지표만 기기에 저장합니다.
- 상대와 서버에는 내가 공개한 특성과 단계만 갑니다. 수치, 순위, 낮은 평가는 상대에게 보이지 않습니다.
- 빠르거나 공격적인 운전을 칭찬하는 특성, 점수, 순위를 만들지 않습니다.
- 주행 중에는 점수나 안내를 보여 주지 않습니다. 결과는 주차 후에만 봅니다.
- 차량이 제공하지 않는 신호는 `이 차량에서 제공되지 않아요`로 표시하고 0으로 계산하지 않습니다.
- VIN, 차량 등록 정보, 차량 모델, 번호, 외형은 읽지 않습니다.
- `혼자 둘러보기`는 첫 선택에서 가상 상대임을 알리고, 내 시그니처 근거에 출처를 한 줄로 보여줍니다. 서버 모드에서는 가상 상대와 합성 데이터의 작은 표시를 유지합니다.

### 핵심 기능

| 기능 | 해결하는 문제 | 차량 특화 요소 |
|---|---|---|
| 발견 켜기/끄기 | 원할 때만 참여합니다. 끄면 새 노출과 요청이 멈춥니다 | 주차 중에만 조작합니다 |
| 집 보호 구역 | 집 근처에서는 발견을 쉬어 집이 추정되는 일을 줄입니다. 이어져 있던 상대에게는 멀어져서 끝난 것과 똑같이 보입니다 | 집 좌표와 반경은 차 안에만 저장하고 서버로 보내지 않습니다 |
| 오늘의 인연 카드 | 칭호, 대표 특성, 잘 맞는 점 수를 관심사보다 먼저 보여 줍니다 | 지도, 거리, 방향, 차량 식별 정보를 표시하지 않습니다 |
| 상호 동의 연결 | 요청과 수락이 모두 있어야 연결됩니다 | 수락 시점에 양쪽이 여전히 근처인지 다시 확인합니다 |
| 일시 연결 음성 통화 | 수락하면 바로 통화를 시작합니다. 주차 중에는 공개 공통 관심사·궁합·칭호를 이야깃거리로 보여 줍니다 | 주행 중 통화를 유지하고 음소거와 통화 끊기만 크게 제공합니다 |
| 멀어지면 자동 종료 | 이동이 끝나면 관계도 자연스럽게 끝납니다 | 차량의 이동이 연결의 시작과 끝을 정합니다 |
| 스친 인연 기록 | 닉네임, 시각, 기간, 끝난 이유만 남깁니다 | 지나온 위치와 경로를 저장하지 않습니다 |
| 애프터 | 양쪽이 다시 원할 때만 새 대화를 엽니다 | 이후에는 거리와 상관없이 이어집니다 |
| 차단·신고·정리 | 차단하면 노출, 요청, 대화가 즉시 끊깁니다 | 로그아웃하면 공유 차량에 개인 정보를 남기지 않습니다 |

### 차량에서만 가능한 경험

- **운전 습관이 자기소개가 됩니다.** 사진과 글로 꾸민 프로필이 아니라, 평소의 주행과 차량 관리로 나를 보여 줍니다. 차 밖에서는 만들 수 없는 프로필입니다.
- **주차하는 순간이 경험의 절정입니다.** 주행이 쌓여 시그니처가 생기면, 주차 후 매듭이 그려지며 내 칭호와 특성을 처음 보여 줍니다.
- **이동이 곧 관계의 규칙입니다.** 휴대폰 앱처럼 언제든 찾아보는 서비스가 아니라, 같은 길 위에 있는 동안만 이어지는 만남입니다.
- **주행 상태에 맞춰 앱이 달라집니다.** 연결을 수락하면 통화를 시작하고 주행 중에도 목소리로 이어가요. 탐색·입력은 잠그고 음소거와 통화 끊기를 제공해요. 기본 OFF 수신 설정을 켠 경우에만 제한 상태에서 아바타·닉네임·칭호로 요청을 받을 수 있어요.
- **붉은 실로 상태를 보여 줍니다.** 뻗은 실은 요청, 이어진 실은 연결, 끊어진 실은 종료, 구슬 줄은 애프터 대기, 매듭은 이어진 인연입니다.

### 안전과 개인정보 원칙

- 상대에게 정확한 좌표, 거리, 방향, 궤적, 차량번호, 차량 외형, 집과 목적지를 제공하지 않습니다.
- 발견을 켜는 것과 개별 연결에 동의하는 것을 분리합니다.
- 주행 중과 상태 불명에서 탐색·발신 요청·입력은 막아요. RESTRICTED의 기본 OFF 수신 설정을 켠 전용 화면만 받기/거절을 허용하며 UNKNOWN에는 이 예외도 없어요.
- 집을 정하면 그 반경 안에서는 발견을 쉽니다. 위치를 확인할 수 없을 때도 쉬는 쪽으로 동작하고, 위치 사용 동의를 끄면 위치 읽기를 멈춥니다.
- 내 위치나 통신이 끊기면 내 화면에 그 사실을 안내합니다. 상대에게는 집 도착, 앱 종료, 통신 단절이 멀어진 경우와 똑같이 보입니다.
- 성인 이용자를 대상으로 합니다. 시연 단계의 자기 확인을 실제 연령 인증으로 표시하지 않습니다.

## 4. 주요 사용 시나리오

**상황:** 서로 모르는 성인 A와 B가 저녁에 같은 휴게 공간에 주차해 있습니다. 두 사람 모두 차연의 발견을 켜 둔 상태입니다.

1. **시그니처:** A는 평소처럼 운전합니다. 유효한 주행이 3번 모이면 주차 후 `내 주행이 매듭이 됐어요`라는 화면에서 매듭과 칭호를 처음 봅니다. 공개할 특성은 A가 고릅니다.
2. **발견:** A는 오늘의 인연에서 B의 카드를 봅니다. 칭호와 대표 특성, 잘 맞는 점 수가 먼저 보이고 관심사가 그다음에 보입니다.
3. **궁합:** B의 카드를 열면 공개 특성과 함께 두 사람의 매듭이 엮인 모습과 `둘 다 출발 전에 안전부터 챙겨요` 같은 문장이 보입니다.
4. **요청:** A가 연결을 요청합니다. B가 수락하기 전에는 대화가 열리지 않습니다.
5. **수락:** B는 A의 칭호와 잘 맞는 점을 보고 결정합니다. 요청 화면에서 통화가 시작됨을 미리 안내하고, 수락하면 두 사람이 바로 음성 통화에 참여해요.
6. **통화:** 목소리로 인사를 나눠요. 주차 중에는 공통 관심사·궁합·칭호를 담은 이야깃거리를 보며 대화를 이어가요. 임시 연결에는 메시지 전송 UI가 없어요.
7. **출발:** 주행으로 바꿔도 통화는 이어져요. 입력은 잠그고 음소거·통화 끊기만 크게 보여줘요.
8. **종료:** 서로 멀어지면 통화와 일시 연결이 끝나고 스친 인연에 기록돼요.
9. **애프터:** 집에 도착한 A가 기록에서 궁합을 다시 보고 애프터를 신청합니다. B가 수락하면 새 대화가 열립니다.

**경계 상황**

| 상황 | 앱의 동작 |
|---|---|
| B가 거절하거나 응답하지 않음 | 연결은 만들어지지 않고 기록에도 남지 않습니다. 거절 이유는 전달하지 않습니다 |
| 수락 시점에 상대가 이미 멀어짐 | 연결할 수 없다고 안내합니다. 다른 사람과 자동으로 연결하지 않습니다 |
| 연결 중에 집 근처에 도착함 | 바로 발견을 쉽니다. 상대에게는 잠시 확인 상태를 거쳐 멀어져서 끝난 것으로 보이고, 집 때문이라는 사실은 전달되지 않습니다 |
| 집 근처에서 요청을 받음 | 수락은 막고 쉬는 동안에는 수락할 수 없다고 안내합니다. 거절은 할 수 있습니다 |
| 불쾌한 상대를 만남 | 차단하면 노출, 요청, 대화가 즉시 끊깁니다 |
| 함께 쓰는 차량에서 내림 | 로그아웃하면 이 차량의 프로필, 대화, 주행 지표가 지워집니다 |
| 다른 사람이 내 계정으로 운전함 | 주행 후 요약에서 `내가 운전하지 않았어요`로 그 주행을 뺍니다 |
| 차량이 일부 신호를 제공하지 않음 | 그 특성은 제공되지 않는다고만 표시합니다. 나쁘게 평가하지 않습니다 |

## 5. 개발 계획

### 구현 범위

| 단계 | 범위 | 시연 표기 |
|---|---|---|
| 1차 제출 (구현 완료) | 드라이브 시그니처, 전체 만남 흐름, 일시 연결 중 음성 통화와 집 보호 구역이 동작합니다. 서버 없이 `혼자 둘러보기`로 시연 상대를 만나고, 서버를 켜면 두 계정이 실제로 연결됩니다 | SOLO는 첫 모드 선택과 내 시그니처 근거에서 출처 안내. 서버 모드는 화면의 작은 표시 유지 |
| 2차 PT | 공개 서버 운영, 화면 분할 등 차량 환경 대응을 넓히고 실차 조건을 확인합니다 | 실제 통신, 합성 위치 |
| 이후 확장 | 실제 위치, Opus 음성 압축, 휴대폰 연동, 서명된 차량 신호, 공개 운영 체계를 더합니다 | 향후 계획 |

### 구조

- **앱:** Kotlin, Jetpack Compose, ViewModel, Repository 구조의 Pleos Connect용 Android 앱입니다. 모듈 의존 규칙은 빌드에서 검사합니다.
- **관계 엔진:** 상호 동의, 근접, 만료, 차단 규칙을 한 모듈에 모았습니다. 서버와 `혼자 둘러보기`가 같은 엔진을 실행해 두 모드의 규칙이 갈라지지 않습니다.
- **서버:** Ktor 단일 서버입니다. 사용자는 인증 토큰으로 식별하고, 클라이언트가 보낸 동의 값을 믿지 않습니다. 상태는 긴 폴링으로 동기화합니다.
- **시그니처 계산:** 순수 Kotlin 모듈로 분리해 같은 입력에 항상 같은 칭호, 궁합, 매듭을 만듭니다.
- **상태 규칙:** 사용자당 활성 일시 연결은 하나입니다. 취소, 만료, 종료는 최종 상태이며 늦게 도착한 수락이나 재접속으로 되살아나지 않습니다.

### 검증 항목

자동 테스트와 에뮬레이터 종단 시나리오로 다음을 확인합니다.

- 일방 요청만으로 대화 채널이 열리지 않습니다.
- 취소, 거절, 만료, 차단 뒤에 도착한 수락은 연결을 만들지 않습니다. 동시 수락과 재전송도 시험합니다.
- 제3의 계정은 다른 사람의 연결, 메시지, 기록을 읽거나 바꿀 수 없습니다.
- 차단당한 사람이 응답이나 동기화로 차단 사실을 알아낼 수 없습니다.
- 서버 응답과 저장 데이터에 위치, 궤적, 원시 신호, 개인 지표가 없습니다.
- 주행 제한과 상태 불명에서 탐색·발신 요청·입력이 막혀요. 제한 상태의 전용 수신 예외는 설정 ON일 때만 열리고 집 보호는 수락을 막아요.
- 공유 차량 로그아웃 뒤 다음 이용자에게 개인 화면과 대화가 남지 않습니다. 집 기록도 지워집니다.
- 집 좌표와 반경이 요청과 응답 형식에 들어가지 않습니다.
- 상대가 받는 전체 동기화 내용과 종료 시각이 서버 만료와 명시적 이탈에서 같습니다.
- 앱이 강제 종료되면 앱의 추가 요청 없이 서버 만료로 연결이 끝납니다.
- 집 보호 중에는 후보가 보이지 않고 요청과 수락이 막히며, 재시도 중에 집 보호가 시작되면 다음 전송을 보내지 않습니다.

### 알려진 한계

- 시그니처는 차량 안 클라이언트에서 계산하므로 변조를 완전히 막지 못합니다. 공개 서비스로 가려면 서명된 차량 신호나 서버 검증이 필요합니다.
- 상대와의 근접 판단은 합성 값입니다. 실제 위치 기반 근접은 구현 경로만 있고 시연하지 않습니다. 기기 위치는 집 보호 구역에만 씁니다.
- 앱이 강제 종료되거나 차 전원이 꺼지면 서버 만료까지 최대 60초 동안 더 발견될 수 있습니다.
- 서버 운영자는 이탈 명령이 도착한 사실을 볼 수 있고, 이번 빌드에는 실제 위치 기반 이탈이 없으므로 집 보호 때문이라고 추측할 수 있습니다. 좌표와 반경은 서버에 가지 않습니다.
- 집을 정한 사용자가 터널이나 지하 주차장에서 위치를 잃으면 발견을 쉬고, 연결 중이었다면 끝날 수 있습니다. 며칠에 걸친 부재 패턴으로 집을 짐작하는 추론은 막지 못합니다.
- 임계값은 제품 기준이며 안전이나 의학 기준이 아닙니다. 실차 센서 노이즈에 맞춘 보정은 하지 않았습니다.
- 공개 서버는 운영하지 않습니다. 앱은 서버 주소가 없으면 `혼자 둘러보기`만 보여 줍니다.

### 이번 제출의 통화 범위

연결 수락은 바로 통화 시작이며, 요청 화면에서 미리 알려요. 주행 중에는 기존 통화를 이어가고 음소거와 통화 끊기를 제공해요. 기본 OFF인 수신 설정을 켜면 제한 상태에서 최소 정보로 새 요청을 받을 수 있어요. 집 보호는 수락과 음성 송수신을 차단해요. 통화 종료는 일시 연결 종료와 같으며 애프터 음성은 이번 범위에 없어요.

PCM16 mono 16 kHz는 방향당 약 256 kbps(프로토콜 overhead 제외), 양방향 합계 약 512 kbps예요. 서버는 짧은 메모리 대기열만 쓰고 녹음·보관·내용 로그를 만들지 않아요. SOLO와 SERVER_DEMO의 모든 데모 상대는 마이크와 음성 WebSocket 없이 Pleos 기기 내 음성을 사용해요. 초기 준비를 요청한 뒤 준비된 세 문장을 재생하고, 문장 시작부터 약 20초 간격을 둬요. 포커스가 있을 때만 재생하고 종료·집 보호에서는 즉시 멈춰요. SDK의 시작 콜백이 실제 소리 시작을 보장하지 않아 발화 중 표시는 제공하지 않아요. 팀의 이전 앱 측정에서 초기 약 4.5초·이후 약 3초 지연이 있었으며, 차연의 기기 측정값은 아니에요.
