# 시그니처 화면 구현 계획

목표: 내 프로필·내 시그니처·특성 상세·공개 범위·주행 후 요약을 실제 저장소 계약에 연결해요.

- [x] 화면별 불변 상태와 ViewModel을 구현해요. 현재 정책 재검사, 중복 방지, 같은 명령 재시도와 개인정보 숨김을 검증해요.
- [x] RedSettings·RedHome·RedCandidate·RedStyle의 PNG와 인라인 스타일을 기준으로 공용 UI 토큰·표면·매듭을 조립해요. 넓은 창은 두 열, 좁은 창은 스크롤하는 한 열이에요.
- [x] 공개 미리보기와 게시 본문은 같은 공개 투영을 사용해요. 특성 변경·주행 제외 후에는 게시 내용도 갱신해요.
- [x] 고정된 navigation 계약의 본문을 교체해요. 화면 밖 이동은 기존 SignatureExit를 사용해요.
- [x] 모든 화면의 주요 상태를 캡처하고 기준 시안과 비교해요. 상호작용·실패·주행 정책 변화 테스트를 추가해요.
- [x] 모듈 단위 테스트, Roborazzi 검증, lint, verifyArchitecture를 실행하고 자체 반박 검토를 해요.

변경 범위는 feature/signature 안으로 제한해요. 공용 계약·빌드 파일은 유지하고 커밋하지 않아요.
공용 시그니처 엔진이 현재 중립 결과만 내는 골격이므로 최종 칭호·매듭 계산은 엔진 트랙 통합 뒤 다시 검증해야 해요.
